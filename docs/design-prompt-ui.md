## ここからプロンプト

あなたにはWebアプリのUI/UXデザインをお願いします。デザインを検討する前に `artifact-design` の設計原則(配色・情報密度・アクセシビリティ)に従ってください。

### 背景・利用者

- システム名: Deep Tracker(RSSリーダー + AIによる要約)
- 利用者は1名のみ。ローカルMac上で動くバッチが購読中のRSSを定期取得し、AI(Claude Code)が週次サマリを作成する。
- 利用シーン:
  1. PC前で、記事一覧やサマリをじっくり読む(広い画面、マウス/キーボード)。
  2. 同一Wi-Fi内のスマートフォン/タブレットから、サマリや新着記事をざっと読む。
- 認証・ログイン画面は不要(ローカルネットワーク内のみで使う)。
- 実装はNext.js(React)。コンポーネント分割を意識した設計を歓迎する。
- スマートフォン(375px〜)とPC(1280px〜)を1つのレイアウトで自然に扱う(CSSのブレークポイントで調整する)。
- ライト/ダークの両テーマに対応する。

### 画面構成(MVP: 4画面 + 設定 + 共通ナビ)

共通ナビ(PCはサイドバー、モバイルはボトムナビまたはハンバーガー)で以下を行き来する。記事一覧のナビ項目には未読件数のバッジを表示する。

1. サマリ(ホーム画面)
   - 最新の週次サマリを最上部に大きく表示する。項目は、対象期間、生成日時、トピックごとの要約、元記事へのリンク。
   - 過去のサマリを一覧・選択できる(期間ごと)。
   - 「今すぐサマリを生成」ボタンと、生成中・失敗(AIの利用制限に達した場合など)の状態表示を持つ。
2. 記事一覧
   - 新着順の記事リスト。表示項目は、タイトル、フィード名、公開日時、本文の抜粋(2行)。
   - 未読/既読を視覚的に区別する(例: 未読は太字+未読ドット、既読は文字色を落とす)。
   - 未読のみ表示/すべて表示の切り替え、フィード別の絞り込み、キーワード検索、期間指定ができる。
   - 各記事に「既読にする/未読に戻す」の操作を持つ。一覧の一括操作として「表示中の記事をすべて既読にする」を用意する(誤操作防止の確認またはUndoあり)。
   - 記事をクリックすると記事詳細へ遷移する。
3. 記事詳細
   - タイトル、フィード名、公開日時、本文(取得できた範囲)、元記事を開くリンク。
   - 開いた時点で自動的に既読になる。詳細画面から「未読に戻す」ができる。
   - 将来「興味あり/なし」ボタンや調査指示の入力欄を追加できる余白を残す(MVPでは表示しない)。
4. 購読フィード管理
   - フィード一覧。表示項目は、名称、URL、最終取得日時、最終取得の成否(エラー時は理由)、取得間隔、記事件数、未読件数、有効/無効。
   - 追加(URL入力)、編集(名称・取得間隔)、削除(確認ダイアログ)、有効/無効の切り替え、「今すぐ取得」、「このフィードをすべて既読にする」ができる。
   - URL追加時の検証エラー(RSSとして解析できない等)の表示を含める。
5. 設定(ナビの末尾) ※差分プロンプトで廃止
   - 記事の保存期間(既定: 1年)、サマリの実行周期(既定: 週次)、Slack通知の有効/無効、LAN公開の案内(設定ファイルで変更する旨の説明表示のみ)。

### 共通のUI状態(すべての画面で設計する)

- 空状態(フィード未登録、記事なし、未読なし、サマリ未生成)。ここでは次にすべき操作へ誘導する。
- 読み込み中、エラー(API接続失敗、AI処理の失敗)、トースト通知。
- 長いタイトルや長文の折り返し・省略ルール。

### デザインの方針

- 読むことが主目的のアプリなので、可読性を最優先にする(本文の行長、行間、日本語の組版)。
- 情報密度は高めだが、圧迫感のない余白にする。
- 装飾は控えめにし、色は状態(成功/失敗/無効/未読)と強調にだけ使う。
- 日本語UIを前提にする。フォント指定は日本語が美しく表示されるものにする。

### 成果物

- HTML/CSSのArtifactとして、ダミーデータを使った動作するモックアップにする(画面遷移も動かす。既読/未読の切り替えも動かす)。
- モバイル幅・PC幅の両方の見え方を確認できるようにする。
- ダミーデータ: 記事は日本語のIT系ニュース(例: AWSのWhat's New風のタイトル)を10件以上(未読・既読を混在させる)、フィードは3〜5件、サマリは2件程度。

プロジェクト名は「Deep Tracker」としてください。不明点があれば、デザインを進める前に質問してください。
