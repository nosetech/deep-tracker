# デザイン差分指示: フィードのグループ (#125)

Claude のチャットに送った変更指示。

```
Deep Trackerのデザインに「購読フィードのグループ」機能のUIを追加してください。マスターの project/Deep Tracker.dc.html は上書きせず、それを複製した新規ファイル project/feature/issue-125-feed-group.dc.html を作成し、そちらに追加してください。既存のレイアウト・配色・コンポーネントの作りは変えず、以下だけを追加します。

前提: AWSの障害情報RSSのように、サービス×リージョンごとに分かれたフィードを数十件登録する使い方があります。フィードを関連するもの同士でグループにまとめ、グループ単位で表示・操作します。グループはフィードと同じ「データ」で、GUIから作成・変更します（アプリの設定ではありません）。1つのフィードは最大1つのグループに属し、どのグループにも属さないフィードは「未分類」です。グループの並び順は名前順で、「未分類」は常に最後です。サンプルデータとして「AWS障害情報」グループ（ec2-ap-northeast-1 など数件）と、もう1つ別のグループ、未分類のフィード数件を用意してください。

1) 購読フィード画面の「登録済み」リスト: フィードをグループごとのセクションで表示する。セクション見出しには、折りたたみ切り替え（シェブロン）・グループ名・件数（フィード数／有効数／エラーがあればエラー数）・未読数を置き、右端にグループ操作の「…」メニューボタンを置く。折りたたみ状態はリロード後も保持する（実装ではlocalStorage）。フィード行そのものの見た目は今のまま。グループに属するフィードが0件でも見出しは表示し、「このグループにはフィードがありません」と出す。グループが1つもない場合は、見出しなしで従来どおりフラットに表示する。
2) グループ見出しの「…」メニュー: 「グループ名を変更」「グループ内をすべて有効にする」「グループ内をすべて無効にする」「グループ内をすべて既読にする」、区切り線、「グループを削除…」（危険色）。「未分類」セクションには「すべて有効/無効/既読」のみ出し、名前変更・削除は出さない。
3) グループ名の変更・作成は既存の「フィードを編集」と同じモーダルの作りで、名称の入力欄1つ。名前の重複時は入力欄の下に既存のエラー表示と同じ見た目で「同じ名前のグループがすでにあります。」を出す。
4) グループの削除は既存のフィード削除と同じ確認モーダル。文言は「グループ「◯◯」を削除します。所属するフィード N件は削除されず「未分類」に移動します。」。
5) グループの新規作成の導線: 「登録済み」見出し行の右側に「グループを作成」ボタン（小さめのアウトラインボタン）を置く。
6) 一括操作のトースト: 一括既読は既存の「すべて既読」と同じく「元に戻す」付きの成功トースト。一括有効/無効は「AWS障害情報 の 12件を無効にしました」のような通常トースト。
7) 「フィードを追加」フォーム: URL入力欄の行に、所属グループの選択欄（セレクト。選択肢は「未分類」、既存グループ、「新しいグループを作成…」）を追加する。「新しいグループを作成…」を選ぶと、その下にグループ名の入力欄が出て、追加時に一緒に作成される。モバイル幅でも崩れない配置にする。
8) 「フィードを編集」モーダル: 名称・URL・取得間隔に加えて「グループ」のセレクト（7と同じ選択肢、新規作成時は名前入力欄）を追加する。フィードの「…」メニューの「名称・URL・取得間隔を編集」の文言は「編集…」程度に短くしてよい。
9) 記事一覧のフィード絞り込み: フィード選択をグループで階層化する。「すべてのフィード」の下に、グループごとに「グループ名（すべて）」を選ぶ項目とその配下のフィード、最後に「未分類」配下のフィードを並べる（セレクトならoptgroup相当）。グループを選んだ場合も期間・キーワード・未読のみ・マーク済みのみと併用できる。
10) 「登録済み」リストの文字列検索欄は置かない（グループの折りたたみで十分とする）。
11) デモ操作バーに、グループの有無（グループあり／グループなし）と、グループ操作の結果（成功／失敗）を切り替える操作を追加（デザイン確認用）。

サイドバーへのグループ表示、ドラッグ&ドロップでの移動、設定画面の追加は不要です。
```
