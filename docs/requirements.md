# Deep Tracker 要件・開発計画

RSSリーダー + AIによる要約システム。元ネタは Inkdrop のノートブック「Deep-Tracker(RSS Reader)」の「Service Concept」。

## 1. コンセプト

- RSSリーダー。取得した情報から、ユーザーが興味のある情報をレコメンドし、さらに詳しい調査を行う。
- 定期的に、どのような情報があったかのサマリを作成する。
- 興味の有無をユーザーに確認して学習し、興味のあるものをレコメンドできるようにする。
- ユーザーが興味のありそうなRSSをレコメンドする。

## 2. システム要件（確定済み）

| 項目               | 内容                                                                                                                                                                                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 実行環境           | ローカルPC（macOS想定）。定期バッチで情報取得                                                                                                                                                                                                         |
| 利用者             | 1名のみ。認証なし（同一Wi-Fi内、外出時はVPN経由）                                                                                                                                                                                                     |
| フロント           | Next.js / TypeScript                                                                                                                                                                                                                                  |
| バック             | Python                                                                                                                                                                                                                                                |
| DB                 | 元記事とAI処理結果を保存（SQLiteに確定。詳細は [architecture.md](./architecture.md)）                                                                                                                                                                 |
| AI                 | ローカルPCの Claude Code（Claude Pro/Max等のサブスクリプション）。Codex・APIへ将来拡張できるよう抽象化する。producer-desk の実装を参考にする                                                                                                          |
| AI利用上限         | アプリ側では設けない。サブスクリプションの制限に達したらエラーを返す                                                                                                                                                                                  |
| 学習方式           | 興味情報とフィードバック履歴をプロンプトに含める（軽量な方式）                                                                                                                                                                                        |
| サマリ             | 週次がデフォルトで周期は変更可能。GUI表示に加え、Slackに通知（通知は定期実行のみ。画面からの手動実行は通知しない）                                                                                                                                    |
| 詳細調査           | 当面はユーザーが調査内容を指示して実行する。自動化の程度は運用しながら検討                                                                                                                                                                            |
| 記事の保存期間     | デフォルト1年。変更可能                                                                                                                                                                                                                               |
| 既読/未読          | 管理する（記事単位。一括既読、フィード単位の一括既読あり）                                                                                                                                                                                            |
| マーク             | 記事単位のON/OFF（1種類）。一覧・詳細から切り替え、一覧を「マーク済みのみ」に絞り込める（フィード・期間・キーワード・未読のみと併用可）。既読/未読とは独立。マーク済みの記事は保存期間による削除の対象外（外すと対象に戻る）                          |
| フィードのグループ | 購読フィードを関連するもの同士でグループにまとめる（1フィードは最大1グループ。どこにも属さないフィードは「未分類」）。グループはGUIで作成・名前変更・削除するデータで、設定ファイルでは扱わない。購読フィード画面はグループごとの見出し付きセクション（名前順、未分類は最後）で表示し、見出しにフィード数・有効数・エラー数・未読数を出す。折りたたみ状態はブラウザに保存する。グループ単位で一括有効/無効・一括既読（元に戻せる）ができる。グループを削除しても、フィードと記事は残り未分類に戻る。フィードの追加時・編集時に所属グループを指定・変更・解除できる。記事一覧はグループ単位で絞り込める（期間・キーワード・未読のみ・マーク済みのみと併用可） |
| 翻訳               | 日本語以外の記事（仮名の比率で判定。漢字のみの中国語も対象）は、取得時にAIでタイトルと本文を日本語に翻訳して別列に保存する（原文は変更しない）。1回の取得で自動翻訳する件数に上限（`translation.max_per_fetch`、既定20件・新しい順）。超過分・過去記事は記事詳細・サマリの元記事プレビューから手動で翻訳できる。翻訳済みは日本語を既定表示し、原文に切り替えられる。長い本文は先頭のみ翻訳する。キーワード検索は訳文も対象 |
| タブへの未読表示   | 未読があれば、ブラウザのタブのタイトル先頭に `(N) `（100件以上は `(99+) `）を付け、ファビコン右上に黄色のドットを重ねる。未読件数は60秒ごとにポーリングし、タブが表示状態に戻ったときと既読操作の直後は即時に再取得する。取得失敗時は前回の件数を維持 |
| LAN公開            | デフォルトは `127.0.0.1`。LAN公開は設定で有効化                                                                                                                                                                                                       |
| 設定               | **GUIからは変更しない。YAML設定ファイルの編集のみ**。反映はアプリの再起動                                                                                                                                                                             |
| 設定ファイルの場所 | アプリケーションの展開先に同梱する（producer-desk と同様）。複数バージョンを並行して動かせるようにする                                                                                                                                                |
| Slack              | Webhook URLを設定ファイルから読み込む                                                                                                                                                                                                                 |
| GUIデザイン        | Claude の Artifacts のデザインを正とする（[CLAUDE.md](../CLAUDE.md) 参照）                                                                                                                                                                            |
| テスト             | RSSとして `https://aws.amazon.com/jp/about-aws/whats-new/recent/feed/` を最低限使う                                                                                                                                                                   |

### 設定ファイルで持つ項目（想定）

保存期間、サマリの実行周期、Slack Webhook URLと通知の有効/無効、記事の自動翻訳の有効/無効と1回の取得あたりの上限、待ち受けホスト・ポート（LAN公開の有効化）、DBのパス。複数バージョンを並行稼働できるよう、DBパスとポートは設定で分けられるようにする。

## 5. アーキテクチャ案

```
[launchd: 定期バッチ] → フィード取得・解析 → DB(元記事)
[launchd: 週次サマリ] → AIProvider(ClaudeCodeCLI) → DB(サマリ) → Slack通知
[Next.js GUI] ⇔ [Python API] ⇔ DB
```

- RSSの取得は必ずバックエンドを経由する（ブラウザから直接取得するとCORSで失敗するため）。
- RSS/Atom/JSON Feedの差異は、パース層で共通の構造に統一する。
- AI呼び出しは `AIProvider` インターフェースの裏に置き、最初は Claude Code CLI 実装のみ。

## 6. 画面

画面は、サマリ / 記事一覧 / 記事詳細 / 購読フィード管理の4画面（ナビは3項目）。設定画面は設けない。

PC表示（720px以上）は、画面上部に全幅のヘッダー（左: アプリ名・バージョン、右: テーマ切り替え）を置き、その下にサイドバー（ナビ・最終取得・取得エラー）と各画面を横に並べる。ヘッダーは固定で、サイドバーと各画面は独立してスクロールする。サイドバーは下部のボタンで折りたためる（PCのみ。幅68pxでアイコンのみ。未読あり・取得エラーありはアイコン右上のドットで示す）。折りたたみ中にマウスを乗せる／フォーカスすると、本文に重ねて一時展開する。折りたたみ状態は localStorage に保存し、再読み込み後も保持する。各画面の横幅はブラウザ幅に合わせて広がり（上限1600px、超えても左寄せ）、記事本文の行長だけは読みやすさのため `38em` に保つ。モバイルは従来どおり上部ヘッダーと下部ナビ。詳細は Claude Design のデザインと、[design-prompt-ui.md](./design-prompt-ui.md)・[design-prompt-ui-diff-remove-settings.md](./design-prompt-ui-diff-remove-settings.md) を参照。
