# Deep Tracker 要件・開発計画

RSSリーダー + AIによる要約システム。元ネタは Inkdrop のノートブック「Deep-Tracker(RSS Reader)」の「Service Concept」。

## 1. コンセプト

- RSSリーダー。取得した情報から、ユーザーが興味のある情報をレコメンドし、さらに詳しい調査を行う。
- 定期的に、どのような情報があったかのサマリを作成する。
- 興味の有無をユーザーに確認して学習し、興味のあるものをレコメンドできるようにする。
- ユーザーが興味のありそうなRSSをレコメンドする。

## 2. システム要件（確定済み）

| 項目 | 内容 |
|---|---|
| 実行環境 | ローカルPC（macOS想定）。定期バッチで情報取得 |
| 利用者 | 1名のみ。認証なし（同一Wi-Fi内、外出時はVPN経由） |
| フロント | Next.js / TypeScript |
| バック | Python |
| DB | 元記事とAI処理結果を保存（SQLiteに確定。詳細は [architecture.md](./architecture.md)） |
| AI | ローカルPCの Claude Code（Claude Pro/Max等のサブスクリプション）。Codex・APIへ将来拡張できるよう抽象化する。producer-desk の実装を参考にする |
| AI利用上限 | アプリ側では設けない。サブスクリプションの制限に達したらエラーを返す |
| 学習方式 | 興味情報とフィードバック履歴をプロンプトに含める（軽量な方式） |
| サマリ | 週次がデフォルトで周期は変更可能。GUI表示に加え、Slackに通知 |
| 詳細調査 | 当面はユーザーが調査内容を指示して実行する。自動化の程度は運用しながら検討 |
| 記事の保存期間 | デフォルト1年。変更可能 |
| 既読/未読 | 管理する（記事単位。一括既読、フィード単位の一括既読あり） |
| LAN公開 | デフォルトは `127.0.0.1`。LAN公開は設定で有効化 |
| 設定 | **GUIからは変更しない。YAML設定ファイルの編集のみ**。反映はアプリの再起動 |
| 設定ファイルの場所 | アプリケーションの展開先に同梱する（producer-desk と同様）。複数バージョンを並行して動かせるようにする |
| Slack | Webhook URLを設定ファイルから読み込む |
| GUIデザイン | Claude Design を正とする（[CLAUDE.md](../CLAUDE.md) 参照） |
| テスト | RSSとして `https://aws.amazon.com/jp/about-aws/whats-new/recent/feed/` を最低限使う |

### 設定ファイルで持つ項目（想定）

保存期間、サマリの実行周期、Slack Webhook URLと通知の有効/無効、待ち受けホスト・ポート（LAN公開の有効化）、DBのパス。複数バージョンを並行稼働できるよう、DBパスとポートは設定で分けられるようにする。

## 3. スコープ

- **MVP: フェーズ 0〜4**
- **追加開発: フェーズ 5〜9**（RSSがなくても更新を検知できるかの技術検証は、MVPに含めず別途開発する）

## 4. フェーズ

| フェーズ | 内容 |
|---|---|
| 0. 基盤 | リポジトリ構成（`backend/`・`frontend/`）、環境整備、CI、`develop` ブランチ運用、producer-desk のClaude Code呼び出し実装の調査 |
| 1. 収集 | DBスキーマ、フィード取得・解析（feedparser想定）、購読フィード管理API、定期バッチ（launchd）、保存期間による削除、YAML設定の読み込み |
| 2. 閲覧GUI | Next.js雛形とデザイン反映、購読フィード管理・記事一覧・記事詳細（既読/未読）、LAN公開設定、テーマ切り替え |
| 3. AI基盤 | AIプロバイダ抽象化とClaude Code CLI実装（利用制限エラーの処理）、AI処理ジョブの実行管理、Slack通知基盤 |
| 4. 週次サマリ | サマリ生成（期間ごとの単純な要約）、定期実行（周期は設定で変更可能）、サマリ表示画面、Slack通知 |
| 5. 興味プロファイル | 興味情報の管理GUI、記事への「興味あり/なし」フィードバック |
| 6. レコメンド | 興味に基づく記事の推薦 |
| 7. 詳細調査 | ユーザー指示型の調査 |
| 8. フィード推薦 | 興味に合う新規RSSの推薦 |
| 9. 更新検知 | RSSのないサイトの更新検知の技術検証。確認頻度はサイトごとに設定可能にする |

## 5. アーキテクチャ案

```
[launchd: 定期バッチ] → フィード取得・解析 → DB(元記事)
[launchd: 週次サマリ] → AIProvider(ClaudeCodeCLI) → DB(サマリ) → Slack通知
[Next.js GUI] ⇔ [Python API] ⇔ DB
```

- RSSの取得は必ずバックエンドを経由する（ブラウザから直接取得するとCORSで失敗するため）。
- RSS/Atom/JSON Feedの差異は、パース層で共通の構造に統一する。
- AI呼び出しは `AIProvider` インターフェースの裏に置き、最初は Claude Code CLI 実装のみ。

## 6. 画面

画面は、サマリ / 記事一覧 / 記事詳細 / 購読フィード管理の4画面（ナビは3項目）。設定画面は設けない。詳細は Claude Design のデザインと、[design-prompt-ui.md](./design-prompt-ui.md)・[design-prompt-ui-diff-remove-settings.md](./design-prompt-ui-diff-remove-settings.md) を参照。
